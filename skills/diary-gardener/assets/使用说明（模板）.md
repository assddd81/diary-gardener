# 📖 使用说明：人做什么，AI 做什么

## 一、你每天只做一件事

打开今日日记（左侧 📅 日历图标点今天，或 `Ctrl+P` 搜 daily），往四个区里**随意**记：

| 区块 | 怎么记 |
|---|---|
| 📥 随手记 | 关键词就行，一句半句都行，别管格式 |
| 📅 会议 | 会名 + 要点 + 人名 |
| 💡 想法 | 半成品也写 |
| ✅ 待办 | `- [ ]` 事项 |

**不需要做**：分类、想标签、想放哪个文件夹、建链接、命名规范——这些全是 AI 的活。

## 二、AI 做什么（在 Claude Code 里说一句话）

| 你说 | AI 做 |
|---|---|
| 「整理日记」 | 处理指定日期日记：按标签体系打标签 → 有价值的内容提炼成知识卡片放 `20 Atlas/卡片/` → 挂到对应 MOC → 建双链 → 待办规整 → 标记 `processed: true`（不会重复整理） |
| 「周回顾」 | 汇总本周日记 + 本周改动，生成周记放 `10 Calendar/` |
| 「找之前关于 XX 的笔记」 | 沿 MOC 和链接检索全库 |
| 「新建项目 XX」 | 在 `30 Efforts/项目/` 建项目骨架并挂到 [[项目总览 MOC]] |
| 「整理 Inbox」 | 把 `00 Inbox` 里的东西归类到对应分区 |

## 三、每周（可选，5 分钟）

1. 周一让 AI 跑一次「周回顾」
2. 瞄一眼项目总览 MOC，删掉完结的、加上新开的

## 四、附件与项目产物的放置规则

| 类型 | 去处 | 例子 |
|---|---|---|
| **随手附件**（粘贴的截图、图片） | `98 附件/`（建议在 Obsidian 设置里把附件目录指向它，粘贴即达） | 日记里贴的截图 |
| **项目产物**（项目的工作产出） | **留在项目文件夹**，与内容同目录 | 文章配图源文件、图表 JSON 规范、HTML 产物、脚本代码 |

判断标准一句话：**这张图是"笔记的插图"还是"项目的交付物"？** 前者进 98 附件，后者跟项目走。

## 五、这套体系的四条地基

1. **链接优先于搬移** —— 卡片用 `[[双链]]` 指向任何位置的文件，文件不用挪
2. **先写后想** —— 日记随便记，想清楚是 AI 帮你慢慢做的
3. **MOC 是地图** —— 每个主题一张地图，AI 维护，你只管看
4. **Inbox 必须清空** —— `00 Inbox` 是中转站不是仓库，定期让 AI 归位

## 六、标签体系（AI 打标签时遵守，人不用记）

```
#会议        会议记录、纪要
#项目/<名>   具体项目（如 #项目/项目A）
#人名        提到的关键人物（如 #张总）
#想法        值得展开的洞察
#待办        未完成事项
#资料        学习资料、剪藏
#生活        家庭、个人事务
#领域        你关注的业务领域
```

新标签由 AI 在整理时提议，你确认后加入本表。
